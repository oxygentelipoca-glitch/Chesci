# ChemFinder 化学合成路线智能分析系统
## 项目概述与需求分析

兰州交通大学 · ChemFinder 团队 · 团队编号 44590

参赛成员  甘祖德、陈俊宏、张意博

面对同一种目标产物，文献里收率最高的反应是否适合本实验室？ChemFinder 把这项判断放在一个 Web 页面里。用户输入起始原料、目标产物和设备上限，查看已发表或自行导入的反应，比较原始条件，最后带着页码和待核实项导出方案草案。

### 一个贯穿评审的例子
起始原料为苯甲醛，目标产物为肉桂酸，设备最高温度为 80 °C。演示库有两条用于检验排序规则的模拟记录，以及一条从公开论文核对的记录。

| 记录 | 收率 | 反应温度记录 | 80 °C 上限的判断 |
|---|---|---|---|
| 模拟 A | 72% | 65 °C | 满足 |
| 模拟 B | 90% | 110 °C | 冲突 |
| 公开论文，化合物 1 | 85.3 ± 2.9% | 回流，5 h | 证据不足 |

### 目标用户与需求
高校化学实验课学生需要知道应读论文的哪一段。课题组成员要在现有仪器条件下预选路线。指导教师需要看见推荐依据，核对学生是否误用了冷却温度或相邻化合物的数据。三类用户都可以从同一条路线回到原始记录。

### 验收标准
导入预览允许纠正字段。改变温度上限后，路线判断随之改变。切换所选路线后，草案中的温度、来源与页码随所选记录更新。输入资料没有足够证据时，页面保留“证据不足”。

> 论文实验段位于期刊第 227 页，收率位于第 228 页表 1。电子版分别为 PDF 第 2、3 页。[实验段](https://journal.ugm.ac.id/ijc/article/download/21626/14331#page=2) · [收率表](https://journal.ugm.ac.id/ijc/article/download/21626/14331#page=3)

## 系统架构设计
浏览器负责录入、校对和并排比较。FastAPI 接收上传与检索请求，模型处理自然语言，关系数据库保存经过用户确认的反应。这样即使评审时没有模型密钥，已入库记录仍可检索、评分和导出。

| 层次 | 主要实现 | 传递的数据 |
|---|---|---|
| Web 界面 | Vue 3、Vue Router、Vite、ECharts | 起始原料、目标产物、实验室约束、用户校对结果 |
| 业务接口 | FastAPI、Pydantic、SQLModel | 已登录的导入请求、结构化预览、反应与来源 |
| 关系数据 | 演示环境使用两个 SQLite 库 | 用户及检索历史存入用户库，反应及其来源存入化学库 |
| 模型与检索 | DeepSeek 兼容接口、Chroma、BM25、BGE | 论文结构化字段、带来源的文档片段、审阅草案 |

### 从文件到可检索的路线
① 上传后，pdfplumber 按页读取文本。② 用户在预览界面检查名称、温度、时间、收率和引文。③ 确认后将反应、条件、文献关联写入化学库。④ 查询时结合目标及起始原料取候选，再按实验室条件排序。⑤ 用户在比较表里选中具体反应，导出沿用这条记录的来源。

### 三条数据路径
路线页查结构化反应库。知识库问答在已索引文档中查找片段。文献搜索页调用 OpenAlex 或 Crossref 获取公开元数据。检索到论文标题之后，实验条件仍须依据原文提取和确认。

> 对照实现可从 app/main.py 进入后端路由，从 frontend/src/views/RoutePlanning.vue 查看一次前端交互。反应数据导入位于 app/chemistry/scifinder_import.py。

## AI 技术方案
### 选型与集成
SciFinder 导出有 Scheme 编号，期刊论文常把条件写在实验段、把收率写在另一页的表格。系统对前者按编号切分，对后者保留每页边界。DeepSeek 兼容接口负责跨语言字段抽取和草案组织。数值比较、证据页定位及排序交给可以重复执行的程序规则。

### 论文抽取的质量控制
| 常见失误 | 系统处理 | 用户看到的结果 |
|---|---|---|
| 选错温度 | 提示词区分反应阶段、冷却、熔点和沸点 | 只有“回流”的记录保留原词 |
| 表格丢失误差 | 要求保留 ± 与单位，并返回产物名称和表格短引文 | 用户能核对数值是否属于当前产物 |
| 页码或引文不符 | 校验 JSON 结构，将引文与所标页的文本规范化后匹配 | 对应字段缺乏有效引文时留空，显示提示 |
| 多个产物套用同一实验段 | 检查条件引文是否被多个产物共用 | 预览提示逐条核对，可清空温度或时间 |

用户确认后才写库。同一 PDF 按文件指纹及已导入 Scheme 识别重复提交。引文匹配能确认文字出现的位置，文字的适用对象由校对者判断。

### 文档问答中的检索增强
化学名称既包含需要精确匹配的编号，也包含可用不同说法表达的概念。BM25 用于词项命中，BGE 向量用于语义召回。两路结果通过倒数排名融合（RRF）合并，可用时再由交叉编码器重排。文档分块保留来源和章节，模型据此组织回答。嵌入模型、索引和重排资源按需加载。

### 生成草案
输入包括所选反应、原始条件、来源和用户约束。提示词要求区分记录值和用户阈值，并标记待核实项。无密钥时，页面生成可编辑的记录草案。两种路径均支持导出 Markdown，保留原始出处供审阅。

## 核心功能与创新点
### 实验室约束优先的路线排序
设定约束后，程序先比较已证实满足的条件数，相同时才比较综合分。综合分由收率 35%、步骤 15%、温度 20%、试剂风险 30% 加权得到。试剂风险分来自记录中的试剂、催化剂与溶剂关键词。卡片展示各项权重、记录值及缺失信息使用的默认分数。默认分数仅参与综合分计算。

| 核对场景 | 程序的处理 |
|---|---|
| 多步反应有一步超过温度上限 | 即使其余步骤缺温度，已知超限仍判为冲突 |
| 已知温度均在上限内，但有步骤缺记录 | 暂列为证据不足 |
| 要求无溶剂，记录的溶剂栏为空 | 空栏无法证明实验采用无溶剂条件 |
| 论文收率为 85.3 ± 2.9%，最低要求 85% | 按报告值加减误差进行筛选，阈值落在区间内，判为证据不足 |

### 技术创新
系统将同一条核对结果用于候选卡、并排比较和导出草案。一次判断同时保留用户要求、记录文本和结论，避免导出时重新推测依据。论文抽取增加页级引文核验与共用引文提示，让用户定位模型可能配错字段的地方。

### 应用创新
把设备能力纳入选线过程，使研究生或教师可以围绕“这条路线是否适合现有设备”讨论。页面允许并排比较高收率但超温的模拟记录，以及条件尚不完整的论文记录。课堂可以据此讲解为何还需要查证。

### 结构和图谱交互
用户可绘制常见原子和键，导出 SVG 或用生成的 SMILES 搜索。当前结构检索依赖与库内记录一致的 SMILES。知识图谱把反应物、产物和相关节点连在一起，辅助浏览已有关系。复杂立体化学和等价结构匹配属于后续工作。

## 测试与部署
### 评审可复现的检查
| 验证项目 | 操作与已观察结果 |
|---|---|
| 从空库开始 | 运行种子脚本两次。同一版本第二次新增 0 条，库中保留两条模拟记录和一条公开论文记录 |
| 条件与排名 | 将上限从 80 °C 改为 45 °C。模拟 A 由满足变为冲突，论文路线仍因缺数字温度而证据不足 |
| 真实 PDF 与在线模型 | 5 页公开论文一次实测提取 7 条记录。肉桂酸的两处引文位于 PDF 第 2、3 页；重复确认新增 0 条 |
| 浏览器与导出 | Edge 用该次模型输出回放预览、确认和检索。下载文件保留文件名、页码、收率和条件判断 |
| 自动化检查 | 8 项单元测试通过。演示接口检查、前端生产构建通过 |

### 本地启动
需要 Python 3.12、uv、Node.js 22.12 或更高版本以及 npm。在仓库根目录开启终端一，执行以下命令启动离线评审环境。
```
uv sync --locked --no-install-project --python 3.12
.venv/bin/python scripts/seed_chemistry.py --directory .chemfinder-demo
export DATABASE_URL="sqlite:///$PWD/.chemfinder-demo/demo-users.db"
export CHEMISTRY_DB_URL="sqlite:///$PWD/.chemfinder-demo/demo-reactions.db"
export DEEPSEEK_API_KEY=""
.venv/bin/python -m uvicorn app.main:app --port 8000
```
终端二进入 frontend，运行 npm ci，再运行 npm run dev。打开终端显示的地址并注册登录。运行 scripts/check_demo.py 可在临时库中复查演示数据和关键 API。

### 在线模型配置
要验证 PDF 提取，按 .env.example 配置 DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、LLM_MODEL。启动后端的 shell 如已把密钥设为空，先取消该覆盖再重启。后端处理上传并把文本发给配置的模型服务，原始上传文件只在请求期间处理。公开部署还需配置 JWT_SECRET 和专用评审账号。

## 总结与展望
这套系统已经能完成从论文导入、校对、检索到草案导出的过程。以苯甲醛到肉桂酸为例，最容易被忽略的信息是作者只记录了“回流”。即使收率写到了小数点后一位，当前证据仍不足以确认设备的温度上限。系统保留这个缺口，把判断交回给能够查阅原文的研究者。

### 已知边界与下一步工作
| 现阶段边界 | 下一步如何验证 |
|---|---|
| 当前实测覆盖一篇公开论文及演示样本 | 扩展跨期刊、跨语言样本，并由两人独立标注产物、收率、条件和页码 |
| 双栏、跨页表格及多个化合物共享实验段会增加配对难度 | 分别统计字段正确率、出处定位率、人工改动次数及误配类型 |
| 缺字段会影响分项评分，风险分依赖关键词 | 对照药品安全资料和专业人员意见，检验已知风险覆盖情况 |
| 复杂结构等价检索与大规模图展示仍有限 | 扩充结构规范化样例，测量大图交互与首屏加载耗时 |
| 当前验证集中在本地评审流程 | 提交版本完成干净环境复测，若提供在线体验，再检查公网稳定性 |

### 评审复查入口
